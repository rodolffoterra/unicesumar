# 📌 Sobre a Aula 01

A primeira aula apresenta a visão geral que orientará toda a disciplina:
**desenvolver software vai muito além de escrever código**.

O objetivo é compreender como **projeto, implementação e testes**
trabalham juntos para transformar uma necessidade em um software
organizado, confiável, sustentável e preparado para evoluir.

O percurso apresentado na aula pode ser resumido assim:

``` text
PROJETO
   ↓
IMPLEMENTAÇÃO
   ↓
TESTES
   ↓
SOFTWARE DE QUALIDADE
```

Ao longo da disciplina, esses conceitos serão aplicados utilizando
principalmente **Python**, boas práticas de organização e ferramentas de
teste.

# 🎯 O que vamos aprender?

A disciplina foi apresentada a partir de cinco grandes frentes:

-   Projeto de Software;

# 🏛️ Os três pilares trabalhados na disciplina

A aula apresenta três grandes pilares:

## 1. Projeto

É o momento de planejar **como o software será construído**.

Antes de programar, precisamos compreender:

-   o problema;
-   os requisitos;
-   a arquitetura;
-   os módulos;
-   os componentes;
-   a comunicação entre as partes;
-   a organização da solução.

## 2. Implementação

É a transformação do projeto em código.

Nesta disciplina, o **Python** será utilizado como uma das principais
tecnologias para implementar as soluções.

## 3. Testes

Os testes ajudam a verificar se aquilo que foi implementado realmente
funciona e atende ao comportamento esperado.

``` text
PROJETO
   ↓
IMPLEMENTAÇÃO
   ↓
TESTES
```

> **Essas etapas trabalham juntas para entregar software de qualidade e
> valor.**

# 💻 Programar é suficiente?

Não.

Escrever código é uma parte importante do desenvolvimento, mas **código
funcionando não garante, sozinho, um bom software**.

Também precisamos de:

``` text
PLANEJAMENTO
ORGANIZAÇÃO
PROCESSOS
DOCUMENTAÇÃO
TESTES
```

Um software desenvolvido sem planejamento e organização tende a
apresentar mais dificuldades de manutenção, evolução e controle.

> **Programar é apenas uma parte do desenvolvimento de software.**

# 🕰️ A origem da Engenharia de Software

A aula também contextualiza historicamente o surgimento da Engenharia de
Software.

Na década de 1960, o crescimento da complexidade dos sistemas trouxe
problemas como:

-   atrasos;
-   projetos cancelados;
-   altos custos;
-   baixa qualidade;
-   dificuldade de manutenção.

Esse cenário ficou associado à chamada **Crise do Software**.

``` text
AUMENTO DA COMPLEXIDADE
          ↓
   CRISE DO SOFTWARE
          ↓
necessidade de métodos,
processos e organização
          ↓
ENGENHARIA DE SOFTWARE
```

A Engenharia de Software surge como uma forma mais sistemática de
planejar, construir, testar, entregar e manter software.

------------------------------------------------------------------------

# ⚙️ O que é Engenharia de Software?

Nesta aula, Engenharia de Software é tratada como um conjunto de
**processos e boas práticas** utilizados para desenvolver sistemas de
forma:

-   organizada;
-   previsível;
-   segura;
-   sustentável;
-   mais fácil de manter.

Ela acompanha todo o ciclo de vida do software.

``` text
REQUISITOS
    ↓
PROJETO
    ↓
IMPLEMENTAÇÃO
    ↓
TESTES
    ↓
IMPLANTAÇÃO
    ↓
MANUTENÇÃO
    ↺
```

Isso mostra que software não termina quando o código fica pronto.

------------------------------------------------------------------------

# ⭐ Por que utilizar Engenharia de Software?

Entre os benefícios apresentados estão:

-   maior qualidade;
-   menos defeitos;
-   maior produtividade;
-   facilidade de manutenção;
-   escalabilidade;
-   segurança.

> **Software organizado custa menos para evoluir.**

A preocupação não é somente fazer o sistema funcionar hoje, mas permitir
que ele continue funcionando e possa ser alterado no futuro.

# 🏗️ Como um software é construído?

Uma visão simplificada apresentada na aula é:

``` text
1. REQUISITOS
      ↓
2. PROJETO
      ↓
3. IMPLEMENTAÇÃO
      ↓
4. TESTES
      ↓
5. EVOLUÇÃO
```

## Requisitos

Levantamento e análise das necessidades do usuário e do negócio.

## Projeto

Planejamento da solução, arquitetura e definição de como o sistema será
construído.

## Implementação

Transformação do projeto em código utilizando linguagens, bibliotecas e
boas práticas.

## Testes

Verificação da qualidade e do funcionamento do software.

## Evolução

Manutenção, adaptação e melhoria contínua para acompanhar novas
necessidades.

> **Cada etapa influencia diretamente a qualidade e o sucesso do
> software.**

A aula apresenta exemplos como:

> **Todos trabalham juntos para entregar software de qualidade e gerar
> valor.**

# 🧱 Como reconhecer um bom projeto?

Um bom projeto deve contribuir para que o software:

-   atenda aos requisitos;
-   permita manutenção;
-   facilite evolução;
-   possibilite reutilização;
-   mantenha organização.

A aula introduz também o **C4 Model** como técnica para documentar e
comunicar arquitetura em diferentes níveis.

``` text
NÍVEL 1
CONTEXTO
   ↓
NÍVEL 2
CONTÊINERES
   ↓
NÍVEL 3
COMPONENTES
   ↓
NÍVEL 4
CÓDIGO
```

### Contexto

Mostra o sistema e sua relação com usuários e outros sistemas.

### Contêineres

Mostra grandes unidades técnicas, como aplicações, serviços e bancos de
dados.

### Componentes

Mostra partes internas relevantes de um contêiner.

### Código

Aprofunda detalhes de implementação.

O objetivo é melhorar a comunicação sobre a arquitetura da solução.

# 🐍 Transformando projeto em código

Depois de planejar, começamos a transformar a solução em implementação.

Durante a disciplina são introduzidos elementos do ecossistema Python
como:

  Conceito         Papel
  ---------------- -----------------------------------------------
  **Python**       Linguagem utilizada na implementação
  **PEP 8**        Convenções de estilo
  **Módulos**      Organização do código em partes reutilizáveis
  **Pacotes**      Agrupamento de módulos
  **pip**          Gerenciamento de pacotes e bibliotecas
  **venv**         Isolamento do ambiente do projeto
  **Docstrings**   Documentação dentro do código

Uma estrutura inicial pode assumir a forma:

``` text
projeto/
│
├── app/
│   ├── __init__.py
│   └── main.py
│
├── tests/
│   └── test_main.py
│
├── venv/
├── requirements.txt
└── README.md
```

Essa organização ajuda na manutenção, leitura e evolução do software.

# ⚠️ Qualidade começa antes da programação

Um dos conceitos centrais da aula é:

> **Código de qualidade começa antes da programação.**

Problemas podem surgir em diferentes etapas.

### Requisitos ruins

Falta de clareza ou inconsistências podem gerar retrabalho e
funcionalidades inadequadas.

### Projeto inadequado

Uma arquitetura mal planejada pode aumentar a complexidade e dificultar
manutenção.

### Implementação incorreta

Código mal escrito pode provocar defeitos, problemas de segurança, baixa
performance e custos maiores de manutenção.

Esses problemas podem resultar em:

``` text
ATRASOS
   +
CUSTOS MAIORES
   +
BAIXA QUALIDADE
   +
DIFICULDADE DE MANUTENÇÃO
   +
INSATISFAÇÃO DO USUÁRIO
```

> **Bons projetos produzem melhores condições para bons códigos.**

# 🧪 Testes de Software

Testar significa verificar o comportamento do software e procurar
evidências de que ele funciona adequadamente.

A aula apresenta diferentes tipos ou níveis de teste:

### Unidade

Testa pequenas partes do código de forma isolada.

### Integração

Verifica a comunicação entre módulos ou componentes.

### Funcionais

Validam se o sistema atende às funcionalidades especificadas.

### Aceitação

Verificam se a solução atende às necessidades do usuário.

### Segurança

Avaliam vulnerabilidades e proteção contra acessos ou comportamentos
indevidos.

A ferramenta apresentada para testes em Python é o **pytest**.

``` text
CÓDIGO
   ↓
TESTES
   ↓
VALIDAÇÃO
   ↓
SOFTWARE MAIS CONFIÁVEL
```

------------------------------------------------------------------------

# ⬅️ Shift Left

Outro conceito introduzido é o **Shift Left**.

A ideia é testar e pensar em qualidade **o quanto antes**.

``` text
PROJETO
   ↓
IMPLEMENTAÇÃO
   ↓
TESTES
   ↓
PRODUÇÃO
```

Em vez de esperar o final para descobrir problemas, verificações podem
acontecer durante todo o processo.

Benefícios destacados:

-   menor custo;
-   menos retrabalho;
-   maior qualidade.

> **Corrigir cedo tende a custar menos do que corrigir tarde.**

------------------------------------------------------------------------

# 📐 PEP 8

A **PEP 8** é apresentada como um guia de estilo para Python.

Ela ajuda a tornar o código:

-   organizado;
-   legível;
-   padronizado;
-   mais fácil de manter;
-   mais adequado ao trabalho em equipe.

Algumas práticas introduzidas:

``` python
def calcular_media(notas):
    total = sum(notas)
    media = total / len(notas)
    return media
```

Também são discutidos:

-   indentação;
-   nomes significativos;
-   organização das importações;
-   espaçamento;
-   tamanho de linhas;
-   comentários;
-   separação entre funções e classes.

Exemplos de convenções:

``` text
Variável → nome_cliente
Função   → calcular_media()
Classe   → ContaBancaria
Constante → MAX_TENTATIVAS
```

> **PEP 8 não é apenas uma regra de aparência: padronização contribui
> para legibilidade e manutenção.**
