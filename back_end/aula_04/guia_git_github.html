Git e GitHub

Guia prático de comandos para transformar uma pasta local em um repositório Git e publicar o projeto no GitHub do início ao fim.

Fluxo completo

Projeto local
↓
Git
↓
Commit
↓
GitHub
↓
Push
1. PrepararEntrar na pasta do projeto.
2. IniciarCriar o repositório Git local.
3. VersionarAdicionar arquivos e criar commit.
4. PublicarConectar ao GitHub e executar push.

1. Entrar na pasta do projeto

Abra o terminal do VS Code, PowerShell, CMD ou Git Bash e navegue até a pasta que será versionada.

Exemplo:
cd C:\Users\SeuUsuario\Desktop\meu_projeto

Confirme se está na pasta correta:

dir

No Git Bash, Linux ou macOS, você também pode usar ls.

2. Configurar Git pela primeira vez

Essa configuração normalmente é feita apenas uma vez no computador.

Definir seu nome:
git config --global user.name "Seu Nome"
Definir seu e-mail:
git config --global user.email "seuemail@exemplo.com"
Verificar a configuração:
git config --global --list

3. Iniciar o repositório local

Dentro da pasta do projeto, execute:

git init
O comando git init transforma a pasta atual em um repositório Git.

Verifique a situação dos arquivos:

git status

4. Criar o arquivo .gitignore

Antes de adicionar os arquivos, é recomendado ignorar itens que não devem ir para o GitHub.

Exemplo para projetos Python:

.venv/
venv/
__pycache__/
*.pyc
.env
logs/
.idea/
.vscode/
Nunca publique senhas, tokens, chaves de API, arquivos .env ou outras credenciais.

5. Adicionar os arquivos ao Git

Para adicionar todos os arquivos da pasta:

git add .

Depois confira:

git status
git add . prepara os arquivos para o próximo commit. Ele ainda não publica nada no GitHub.

6. Criar o primeiro commit

O commit registra um ponto da evolução do projeto.

git commit -m "Primeiro commit"

Outros exemplos:

git commit -m "Cria estrutura inicial do projeto"
git commit -m "Adiciona API FastAPI"
git commit -m "Corrige conexão com banco de dados"

7. Criar um repositório no GitHub

  1. Acesse o GitHub.
  2. Clique em New repository.
  3. Informe o nome do repositório.
  4. Escolha se ele será público ou privado.
  5. Clique em Create repository.
Se o projeto já existe localmente, prefira criar o repositório remoto vazio, sem README, .gitignore ou licença.

8. Conectar o projeto local ao GitHub

Copie a URL HTTPS do repositório criado e execute:

git remote add origin https://github.com/SEU_USUARIO/SEU_REPOSITORIO.git

Confirme a conexão:

git remote -v

9. Definir a branch principal

Para padronizar a branch principal como main:

git branch -M main

10. Enviar o projeto para o GitHub

Agora faça o primeiro envio:

git push -u origin main
Depois desse comando, o projeto local estará publicado no repositório remoto do GitHub.

Sequência completa para um projeto novo

Depois de criar o repositório vazio no GitHub, esta é a sequência principal:

cd caminho\do\projeto

git init

git status

git add .

git commit -m "Primeiro commit"

git branch -M main

git remote add origin https://github.com/SEU_USUARIO/SEU_REPOSITORIO.git

git push -u origin main

Depois do primeiro push

Quando fizer novas alterações, o fluxo fica menor:

git status

git add .

git commit -m "Descrição da alteração"

git push
Alterar arquivo → git add → git commit → git push

Comandos importantes do dia a dia

Ver situação do projeto

git status

Ver histórico de commits

git log

Ver histórico resumido

git log --oneline

Ver repositório remoto

git remote -v

Baixar atualizações do GitHub

git pull

Enviar novos commits

git push

Clonar um repositório existente

Se o projeto já existe no GitHub e você deseja baixá-lo:

git clone https://github.com/SEU_USUARIO/SEU_REPOSITORIO.git

Depois entre na pasta criada:

cd SEU_REPOSITORIO

E verifique:

git status

Quando o remote origin já existe

Se aparecer a mensagem remote origin already exists, primeiro verifique:

git remote -v

Para trocar a URL:

git remote set-url origin https://github.com/SEU_USUARIO/NOVO_REPOSITORIO.git

Quando o repositório remoto já possui arquivos

Se o GitHub já possuir README ou outro commit, pode ser necessário baixar antes de enviar:

git pull origin main --rebase

Depois:

git push -u origin main

Resumo final

  • git init — inicia o versionamento.
  • git status — mostra o estado dos arquivos.
  • git add . — prepara os arquivos.
  • git commit — registra uma versão.
  • git remote add origin — conecta ao GitHub.
  • git branch -M main — define a branch principal.
  • git push — envia commits para o GitHub.
  • git pull — baixa alterações do GitHub.
  • git clone — copia um repositório existente.
Fluxo essencial:
git init → git add . → git commit → git remote → git push
