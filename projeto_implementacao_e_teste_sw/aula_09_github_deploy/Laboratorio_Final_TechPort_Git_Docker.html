📁 Projeto atual

Começando pela raiz do TechPort

Seu projeto está nessa estrutura geral:

aula_08/ ├── app/ │ ├── api/ │ ├── app/ │ │ ├── api/ │ │ ├── core/ │ │ ├── database/ │ │ ├── models/ │ │ ├── pages/ │ │ ├── repositories/ │ │ ├── schemas/ │ │ ├── services/ │ │ └── utils/ │ ├── core/ │ ├── docs/ │ ├── models/ │ ├── pages/ │ ├── repositories/ │ ├── schemas/ │ ├── services/ │ ├── tests/ │ └── utils/ ├── docs/ └── tests/
Atenção: como existe uma pasta app/app, confirme onde estão os arquivos de entrada reais antes de copiar os Dockerfiles.
Get-ChildItem -Recurse -Filter "laboratorio_aula08.py"
Get-ChildItem -Recurse -Filter "fastapi_app.py"
Get-ChildItem -Recurse -Filter "requirements.txt"

Nos exemplos abaixo consideramos os caminhos trabalhados no laboratório: app/laboratorio_aula08.py e app/api/fastapi_app.py. Ajuste se o resultado acima indicar outro local.

① Git + GitHub

Registrar a versão final

1
Verificar alterações
git status
2
Adicionar arquivos
git add .

Criar o commit
git commit -m "Finaliza TechPort para laboratório de deploy"
4
Enviar para o GitHub
git push
✅ Abra o GitHub e mostre aos alunos o commit publicado. A partir daqui, o código já possui uma versão identificada e compartilhável.
② Docker no Windows

Instalar Docker Desktop e Docker Compose

No Windows 10/11, a forma mais simples é usar Docker Desktop. Ele já inclui Docker Engine, Docker CLI e Docker Compose.

1. Verificar WSL
wsl --status

Se não estiver instalado:

wsl --install

Reinicie o Windows se solicitado.

2. Instalar Docker Desktop

Baixe o Docker Desktop no site oficial Docker, execute o instalador e use o backend WSL 2 quando disponível.

Depois, abra o Docker Desktop e aguarde o Engine iniciar.

💡 No Docker Desktop, o Compose já vem incluído. Use docker compose (sem hífen), que é a sintaxe atual.
③ Verificação

Confirmar que o Docker está funcionando

docker --version
docker compose version
docker info

Faça um teste simples:

docker run hello-world
Se o hello-world executar, o ambiente Docker está pronto para o laboratório.

Dockerfile.streamlit

FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 8501

ENV API_BASE_URL=http://host.docker.internal:8000

CMD ["python", "-m", "streamlit", "run", "app/laboratorio_aula08.py", "--server.address=0.0.0.0", "--server.port=8501"]
Se o seu arquivo Streamlit estiver dentro de app/app/..., altere somente o caminho no CMD.

Dockerfile.api — para o modo completo

FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 8000

CMD ["python", "-m", "uvicorn", "app.api.fastapi_app:app", "--host", "0.0.0.0", "--port", "8000"]
⑤ Build + Run

Construir e executar uma imagem

Na raiz do projeto:

docker build -f Dockerfile.streamlit -t techport-streamlit:1.0 .

Verifique a imagem:

docker images

Execute:

docker run --name techport-streamlit -p 8501:8501 techport-streamlit:1.0

Abra no navegador:

http://localhost:8501

⑥ Docker Compose

Subir Streamlit + FastAPI + MySQL juntos

STREAMLIT :8501
↔
FASTAPI :8000
↔
MYSQL :3306

docker-compose.yml

services:
  mysql:
    image: mysql:8.4
    container_name: techport-mysql
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: techport
      MYSQL_USER: techport
      MYSQL_PASSWORD: ${MYSQL_PASSWORD}
    ports:
      - "3306:3306"
    volumes:
      - techport_mysql:/var/lib/mysql
    networks:
      - techport-net

  api:
    build:
      context: .
      dockerfile: Dockerfile.api
    container_name: techport-api
    depends_on:
      - mysql
    environment:
      DB_HOST: mysql
      DB_PORT: 3306
      DB_DATABASE: techport
      DB_USER: techport
      DB_PASSWORD: ${MYSQL_PASSWORD}
    ports:
      - "8000:8000"
    networks:
      - techport-net

  streamlit:
    build:
      context: .
      dockerfile: Dockerfile.streamlit
    container_name: techport-streamlit
    depends_on:
      - api
    environment:
      API_BASE_URL: http://api:8000
    ports:
      - "8501:8501"
    networks:
      - techport-net

volumes:
  techport_mysql:

networks:
  techport-net:

.env para o Compose

MYSQL_ROOT_PASSWORD=troque_esta_senha
MYSQL_PASSWORD=troque_esta_senha
Não envie o .env ao GitHub. Mantenha-o no .gitignore.

Comandos

docker compose up --build

docker compose ps

docker compose logs -f

docker compose down
Se quiser usar seu MySQL do Windows: remova o serviço mysql e configure a API com DB_HOST=host.docker.internal.
⑦ Docker Hub

Publicar a imagem Docker

Um registry guarda imagens prontas para uso. O fluxo é semelhante ao GitHub, mas para imagens Docker.

1
Crie uma conta/repositório no Docker Hub.

Exemplo de repositório: techport.

2
Login no terminal
docker login
3
Tag da imagem
docker tag techport-streamlit:1.0 SEU_USUARIO/techport:1.0
4
Push
docker push SEU_USUARIO/techport:1.0
5
Testar em outra máquina
docker pull SEU_USUARIO/techport:1.0

docker run -p 8501:8501 SEU_USUARIO/techport:1.0

🧯 Diagnóstico

Erros comuns

Docker não reconhecido

Abra o Docker Desktop, aguarde o Engine iniciar e reabra o PowerShell.

Porta 8501 ocupada

docker run -p 8502:8501 techport-streamlit:1.0

Streamlit não encontra FastAPI

FastAPI no Windows:

API_BASE_URL=http://host.docker.internal:8000

FastAPI no Compose:

API_BASE_URL=http://api:8000

API não encontra MySQL

MySQL no Compose:

DB_HOST=mysql

MySQL no Windows:

DB_HOST=host.docker.internal
