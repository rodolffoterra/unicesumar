# Atividade de Estudo 01 - 743074

## Questão 01 — Discursiva

### Tema

**Qualidade de Software**

### Enunciado

Uma empresa desenvolveu um sistema para gerenciamento de uma biblioteca. O software realiza corretamente todas as funcionalidades solicitadas, como cadastro de livros, empréstimos e devoluções. Entretanto, os usuários reclamam que o sistema é lento, difícil de utilizar e apresenta falhas frequentes após novas atualizações.

Com base nos conteúdos estudados nas primeiras unidades da disciplina, explique por que o software não pode ser considerado um software de qualidade, mesmo atendendo aos requisitos funcionais. Apresente pelo menos quatro características de qualidade ou conceitos estudados e explique como eles poderiam contribuir para melhorar o sistema.

---

## Resposta

Embora o sistema da biblioteca execute corretamente suas funcionalidades, como cadastro de livros, empréstimos e devoluções, ele não pode ser considerado um software de qualidade apenas por atender aos requisitos funcionais. A qualidade de software envolve também características não funcionais, como usabilidade, eficiência de desempenho, confiabilidade, manutenibilidade e segurança.

Um software de qualidade deve atender às necessidades dos usuários e apresentar um comportamento adequado durante sua utilização. No caso apresentado, existem problemas que afetam diretamente a experiência dos usuários e a evolução do sistema.

### 1. Usabilidade

O sistema é considerado difícil de utilizar pelos usuários, o que caracteriza um problema de **usabilidade**.

A usabilidade está relacionada à facilidade de aprendizagem, compreensão e utilização do software. Um sistema com boa usabilidade permite que os usuários realizem suas tarefas de maneira mais simples, reduzindo erros e a necessidade de treinamento.

Para melhorar esse aspecto, poderiam ser realizadas melhorias nas telas, simplificação dos menus, organização da navegação e testes de usabilidade com usuários reais.

### 2. Eficiência de Desempenho

A lentidão apresentada pelo sistema demonstra um problema relacionado à **eficiência de desempenho**.

Essa característica está relacionada ao tempo de resposta do sistema, ao consumo de recursos e à capacidade de atender adequadamente aos usuários.

Para solucionar o problema, poderiam ser realizadas otimizações nas consultas ao banco de dados, melhorias nos algoritmos, ajustes na infraestrutura e testes de desempenho para identificar possíveis gargalos.

### 3. Confiabilidade

As falhas frequentes após novas atualizações demonstram problemas de **confiabilidade**.

A confiabilidade representa a capacidade do software de funcionar corretamente durante determinado período, sem apresentar falhas inesperadas.

Para aumentar a confiabilidade, a empresa poderia utilizar testes automatizados, testes de regressão, revisão de código, integração contínua e monitoramento do sistema em produção.

### 4. Manutenibilidade

As falhas introduzidas após atualizações também podem indicar problemas de **manutenibilidade**.

A manutenibilidade representa a facilidade de corrigir defeitos, realizar alterações e implementar novas funcionalidades no software.

Para melhorar essa característica, é importante utilizar código limpo e organizado, documentação adequada, modularização, padronização do desenvolvimento e boas práticas de engenharia de software.

### 5. Segurança

A **segurança** também é uma característica importante para um sistema de biblioteca, principalmente porque ele pode armazenar informações de usuários e registros de empréstimos.

Entre as medidas que podem contribuir para a segurança estão autenticação de usuários, controle de acesso, criptografia de informações, realização de backups e proteção contra possíveis ataques.

Mesmo que o cenário não apresente problemas de segurança, essa característica deve ser considerada durante o desenvolvimento e a manutenção do sistema.

### 6. Compatibilidade

A **compatibilidade** está relacionada à capacidade do software de funcionar adequadamente em diferentes ambientes e de interagir com outros sistemas quando necessário.

Um sistema de biblioteca deve, por exemplo, apresentar funcionamento adequado nos navegadores e ambientes utilizados pela instituição. Problemas de compatibilidade podem prejudicar a experiência dos usuários.

### 7. Portabilidade

A **portabilidade** representa a capacidade de adaptar ou transferir o software para diferentes ambientes, plataformas ou infraestruturas.

Essa característica pode ser importante caso a biblioteca precise migrar o sistema para outro servidor, infraestrutura ou plataforma no futuro.

### 8. Adequação Funcional

A **adequação funcional** está relacionada à capacidade do software de fornecer as funcionalidades necessárias para atender às necessidades especificadas.

No cenário apresentado, o sistema possui adequação funcional, pois consegue realizar as funções solicitadas, como cadastro de livros, empréstimos e devoluções.

Entretanto, essa característica isoladamente não é suficiente para garantir a qualidade do software. O sistema também precisa apresentar bom desempenho, facilidade de uso, confiabilidade, segurança e facilidade de manutenção.

---

## Relação com normas e modelos de qualidade

A qualidade de software não depende apenas do produto final, mas também dos processos utilizados durante seu desenvolvimento.

Modelos e normas como a **ISO/IEC 25010**, o **CMMI** e o **MPS.BR** podem auxiliar as organizações na definição, avaliação e melhoria da qualidade dos produtos e processos de software.

A ISO/IEC 25010, por exemplo, apresenta características de qualidade que permitem avaliar diferentes aspectos de um software, indo além de verificar simplesmente se suas funcionalidades estão funcionando.

Dessa forma, a empresa poderia utilizar práticas de melhoria contínua, processos de testes, padrões de desenvolvimento e métricas de qualidade para identificar problemas antes que eles cheguem aos usuários.

---

## Conclusão

Portanto, o sistema da biblioteca não pode ser considerado um software de qualidade apenas porque suas funcionalidades principais estão funcionando corretamente. Os problemas de usabilidade, desempenho e confiabilidade demonstram que existem deficiências importantes no produto.

A qualidade de software deve ser analisada de forma abrangente, considerando tanto os requisitos funcionais quanto os requisitos não funcionais. Características como **usabilidade, eficiência de desempenho, confiabilidade, manutenibilidade, segurança, compatibilidade e portabilidade** contribuem para que o software seja mais adequado às necessidades dos usuários e possa evoluir de maneira sustentável.

Além disso, a adoção de normas, modelos e boas práticas de desenvolvimento contribui para melhorar não apenas o produto final, mas também os processos utilizados para construí-lo e mantê-lo.
