O arquivo app/.env não será copiado para dentro da imagem. O Docker Compose vai fornecê-lo em tempo de execução.
3 — FastAPI

Criar Dockerfile.api na raiz

FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 8000

CMD ["python", "-m", "uvicorn", "app.api.fastapi_app:app", "--host", "0.0.0.0", "--port", "8000"]
app.api.fastapi_app:app corresponde ao arquivo confirmado em techport/app/api/fastapi_app.py.
4 — Streamlit

Criar Dockerfile.streamlit na raiz

FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 8501

CMD ["python", "-m", "streamlit", "run", "app/laboratorio_aula08.py", "--server.address=0.0.0.0", "--server.port=8501"]
O caminho app/laboratorio_aula08.py foi confirmado no seu projeto.
5 — Docker Compose

Criar docker-compose.yml na raiz

services:
  api:
    build:
      context: .
      dockerfile: Dockerfile.api
    container_name: techport-api
    ports:
      - "8000:8000"
    env_file:
      - ./app/.env
    environment:
      DB_HOST: host.docker.internal
    extra_hosts:
      - "host.docker.internal:host-gateway"
    restart: unless-stopped

  streamlit:
    build:
      context: .
      dockerfile: Dockerfile.streamlit
    container_name: techport-streamlit
    ports:
      - "8501:8501"
    env_file:
      - ./app/.env
    environment:
      API_BASE_URL: http://api:8000
    depends_on:
      - api
    restart: unless-stopped

Ponto importante: se sua aplicação não lê DB_HOST e API_BASE_URL do ambiente, será necessário ajustar o arquivo de configuração Python. O Compose só consegue sobrescrever valores que o código realmente consulta.
6 — Build

Construir as imagens

Antes de executar: confirme que os dois CMD dos Dockerfiles estão em uma única linha. Isso evita erro de sintaxe durante a leitura do Dockerfile.

Dockerfile.api — linha correta

CMD ["python", "-m", "uvicorn", "app.api.fastapi_app:app", "--host", "0.0.0.0", "--port", "8000"]

Dockerfile.streamlit — linha correta

CMD ["python", "-m", "streamlit", "run", "app/laboratorio_aula08.py", "--server.address=0.0.0.0", "--server.port=8501"]

Agora execute um build limpo:

docker compose build --no-cache

Quando o build terminar sem erros, confirme as imagens:

docker images
Resultado esperado: devem aparecer imagens do TechPort, como techport-api e techport-streamlit.
Se aparecer erro apontando para uma linha do CMD: revise se ele está realmente em uma única linha e sem quebras entre os argumentos.

7 — Run

Subir a aplicação

Primeiro rode com os logs visíveis:

docker compose up

Se funcionar, pare com Ctrl+C e suba em segundo plano:

docker compose up -d

Para reconstruir e subir:

docker compose up -d --build
8 — Validação

Validar o TechPort

Streamlit
http://localhost:8501

A interface deve abrir.

FastAPI
http://localhost:8000/docs

O Swagger deve abrir.

MySQL

Crie ou altere um chamado e confirme a persistência no banco local.

Teste funcional recomendado

  1. Abra o Streamlit.
  2. Entre como Usuário.
  3. Crie um chamado.
  4. Troque para Técnico.
  5. Assuma o chamado e atualize o status.
  6. Volte ao Usuário e confirme a alteração.
  7. Abra o Administrador e inspecione o chamado.
  8. Confira o registro no MySQL.
Se o fluxo funcionar, você validou a cadeia Streamlit → FastAPI → MySQL com a aplicação containerizada.

11 — Troubleshooting

Erros comuns

API não inicia

docker logs techport-api

Se aparecer erro de importação, confirme que o módulo principal continua sendo app.api.fastapi_app:app.

Streamlit não inicia

docker logs techport-streamlit

Streamlit tenta acessar 127.0.0.1:8000

Dentro do container, o endereço correto da API é:

http://api:8000

O código deve utilizar a variável API_BASE_URL.

API não conecta ao MySQL

O host precisa ser:

host.docker.internal

Confirme também se o MySQL aceita conexão pela porta 3306.

Porta ocupada

netstat -ano | findstr :8501
netstat -ano | findstr :8000

Erro de sintaxe no Dockerfile durante o build

Se o erro apontar para uma linha como "app/laboratorio_aula08.py", normalmente o CMD foi quebrado em várias linhas.

Use:

CMD ["python", "-m", "streamlit", "run", "app/laboratorio_aula08.py", "--server.address=0.0.0.0", "--server.port=8501"]

E para a API:

CMD ["python", "-m", "uvicorn", "app.api.fastapi_app:app", "--host", "0.0.0.0", "--port", "8000"]

Alterou dependências ou Dockerfiles?

docker compose build --no-cache
docker compose up

🔄 Refazer o laboratório

Excluir e reconstruir o TechPort do zero

Para repetir todo o processo de criação das imagens e execução dos containers, utilize exatamente esta sequência:

# 1. Derrubar os containers
docker compose down

# 2. Excluir as imagens do TechPort
docker rmi techport-api:latest techport-streamlit:latest

# 3. Confirmar que foram removidas
docker images

# 4. Construir novamente
docker compose build --no-cache

# 5. Confirmar que as imagens foram recriadas
docker images

# 6. Executar
docker compose up
