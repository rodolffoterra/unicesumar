Laboratório Final — API TechPort

FastAPI + Swagger + MySQL — criação, consulta, alteração e exclusão de registros
Professor: Rodolfo Terra LinkedIn: linkedin.com/in/rodolffoterra GitHub: github.com/rodolffoterra

Objetivo do laboratório

Ao final deste laboratório, o aluno deverá ser capaz de executar a API TechPort, acessar o Swagger, criar um usuário pela API, validar a persistência no MySQL, consultar o registro criado e, por fim, excluir o mesmo registro pela API.

Swagger → FastAPI → Service → Repository → MySQL

1Entrar na pasta do projeto

No terminal do VS Code, acesse a raiz do projeto techport.

cd "C:\Users\rodolfo\Desktop\cesumar\Disciplinas\Projeto, Implementação e Teste de SW\aula_05\techport"

2Ativar o ambiente virtual

Se o projeto estiver utilizando uma virtual environment, ative-a antes de iniciar a API.

.\.venv\Scripts\Activate.ps1
Observação: se a pasta da sua virtual environment tiver outro nome, ajuste o comando.

3Iniciar a API

Execute o Uvicorn apontando para a aplicação FastAPI:

python -m uvicorn app.api.fastapi_app:app --reload

Quando aparecer algo semelhante ao conteúdo abaixo, a API estará funcionando:

Uvicorn running on http://127.0.0.1:8000

4Acessar o Swagger

Abra o navegador e acesse:

http://127.0.0.1:8000/docs

No Swagger, localize o grupo Usuários. Ele deverá apresentar operações como GET, POST, PUT e DELETE.

5Selecionar o banco TechPort no MySQL

No MySQL Workbench ou em outro cliente MySQL, execute:

USE techport;

Confirme as tabelas existentes:

SHOW TABLES;

6Contar quantos usuários existem

Antes de criar um novo registro, conte a quantidade atual de usuários:

SELECT COUNT(*) AS total_usuarios
FROM usuarios;
Anote o valor retornado. Exemplo: 1000 usuários.

7Visualizar os últimos usuários

Execute uma consulta para visualizar os registros mais recentes:

SELECT
    id,
    nome,
    email,
    perfil,
    ativo,
    data_cadastro
FROM usuarios
ORDER BY id DESC
LIMIT 10;

8Criar um novo usuário pelo Swagger

No Swagger, abra:

POST /usuarios

Clique em Try it out e utilize um JSON de teste:

{
  "nome": "Usuario Aula API",
  "email": "usuario.aula.api@techport.com",
  "senha_hash": "teste123",
  "perfil": "cliente",
  "ativo": true
}

Depois clique em Execute.

A resposta esperada será semelhante a:

{
  "mensagem": "Usuário cadastrado com sucesso.",
  "id": 1001
}

9Contar novamente no MySQL

Volte ao MySQL e execute:

SELECT COUNT(*) AS total_usuarios
FROM usuarios;

Se antes existiam 1000 registros, agora deverá aparecer 1001.

10Consultar o registro criado no MySQL

Confirme que o registro criado pela API está realmente persistido no banco:

SELECT
    id,
    nome,
    email,
    perfil,
    ativo,
    data_cadastro
FROM usuarios
WHERE email = 'usuario.aula.api@techport.com';

Observe que no JSON utilizamos true, enquanto no MySQL o campo tinyint(1) normalmente aparece como 1.

11Consultar o mesmo usuário pela API

No Swagger, abra:

GET /usuarios/{usuario_id}

Informe o ID criado no POST, por exemplo:

1001

A API deverá retornar os dados daquele usuário em formato JSON.

12Excluir o usuário pelo Swagger

No Swagger, abra:

DELETE /usuarios/{usuario_id}

Informe o mesmo ID utilizado anteriormente e clique em Execute.

A resposta esperada será:

{
  "mensagem": "Usuário excluído com sucesso."
}
Atenção: utilize um usuário criado especificamente para o laboratório. Usuários que já possuem chamados, comentários, histórico ou anexos podem não ser excluídos devido às chaves estrangeiras do banco.

13Contar novamente após o DELETE

SELECT COUNT(*) AS total_usuarios
FROM usuarios;

Se o usuário foi excluído corretamente, a quantidade deverá voltar ao valor inicial.

14Confirmar que o registro foi removido

SELECT *
FROM usuarios
WHERE email = 'usuario.aula.api@techport.com';

O resultado esperado é zero registros.

Checklist do laboratório

  • API iniciada com Uvicorn.
  • Swagger acessível em /docs.
  • Banco techport selecionado.
  • Quantidade inicial de usuários anotada.
  • Novo usuário criado com POST.
  • Usuário encontrado no MySQL.
  • Usuário consultado por GET.
  • Usuário excluído por DELETE.
  • Exclusão confirmada no MySQL.

Conclusão

Neste laboratório foi possível comprovar que o Swagger não trabalha com uma cópia isolada dos dados. As requisições HTTP são processadas pelo FastAPI, passam pelas camadas de serviço e repositório e executam operações reais no banco MySQL.

Swagger → FastAPI → Service → Repository → MySQL → COMMIT
